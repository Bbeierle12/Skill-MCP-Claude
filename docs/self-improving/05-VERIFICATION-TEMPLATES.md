# Deliverable 4 — Auto-Verification Templates (fail-fast preconditions)

A generated skill can ship a **check script** that an agent runs *before* attempting the task. If the environment isn't ready, the agent fails fast with a remediation hint instead of reproducing the original failure. This converts a skill from passive documentation into an active precondition gate.

Builds on an existing convention: `core/skills.py` already exposes `has_scripts = (skill_dir / "scripts").exists()`, so `scripts/` is a recognized, served location.

---

## 1. Contract

- **Location:** `skills/<name>/scripts/verify.sh` (POSIX sh) or `verify.py` (Python 3). Prefer `.sh`; use `.py` only when the check needs real parsing.
- **Exit code is the result:** `0` = environment ready, non-zero = not ready.
- **Last stdout line is machine-readable:**
  ```
  VERIFY: ok
  VERIFY: fail reason="<short>" fix="<one-line remediation>"
  ```
- **Properties (enforced by the synthesis safety scan, `04 §4.5`):**
  - **Idempotent & read-only** — checks state, changes nothing. No installs, no writes outside `$TMPDIR`.
  - **Fast** — target < 5 s; no network unless the precondition is network reachability.
  - **No destructive verbs** — `rm -rf /`, `dd`, `mkfs`, `curl … | sh` are rejected at synthesis time.
  - **Self-contained** — only the tools the skill is about; degrade gracefully if a tool is absent (that's a `fail`, not a crash).

---

## 2. Template — `verify.sh`

```sh
#!/bin/sh
# verify.sh — precondition check for skill: <name>
# Generated by the reflection engine from cluster <cluster_key>.
# Exit 0 = ready to attempt the task; non-zero = not ready (see VERIFY line).
set -u

fail() { printf 'VERIFY: fail reason="%s" fix="%s"\n' "$1" "$2" >&2; exit 1; }

# --- checks derived from the cluster's resolutions -------------------------
# Example: cluster fix was "use python3, not python" + "/tmp is noexec"
command -v cargo >/dev/null 2>&1 || fail "cargo not found" "install rust toolchain via rustup"

# $TMPDIR must be executable (this repo's /tmp is mounted noexec)
TMP="${TMPDIR:-/tmp}"
probe="$TMP/.verify_exec_$$"
printf '#!/bin/sh\nexit 0\n' > "$probe" 2>/dev/null && chmod +x "$probe" 2>/dev/null
if ! "$probe" 2>/dev/null; then
  rm -f "$probe"
  fail "TMPDIR is noexec" "export TMPDIR=\$HOME/.cache CARGO_TARGET_DIR=\$HOME/.cache/target"
fi
rm -f "$probe"
# --------------------------------------------------------------------------

printf 'VERIFY: ok\n'
exit 0
```

## 3. Template — `verify.py` (when parsing is needed)

```python
#!/usr/bin/env python3
"""verify.py — precondition check for skill: <name>. Exit 0 = ready."""
import shutil, sys, os

def fail(reason, fix):
    print(f'VERIFY: fail reason="{reason}" fix="{fix}"', file=sys.stderr)
    sys.exit(1)

# Example precondition: a Python venv with 'pypdf' must be importable
if shutil.which("python3") is None:
    fail("python3 missing", "install python3 (do NOT assume 'python' exists)")
try:
    import importlib.util as u
    if u.find_spec("pypdf") is None:
        fail("pypdf not installed", "pip install -r requirements.txt in the project venv")
except Exception as e:  # never crash; absence == fail
    fail("import probe failed", str(e))

print("VERIFY: ok")
```

---

## 4. How the synthesis engine generates it

The check is **derived from the cluster's resolutions**, not hand-written:

| Resolution text pattern in logs | Generated check |
|---|---|
| "install X" / "X: command not found" | `command -v X \|\| fail …` |
| "use python3 not python" | `command -v python3 \|\| fail` |
| "/tmp is noexec" / "permission denied (os error 13)" | the `$TMPDIR` exec probe above |
| "wrong node version" / Vite/module error | `node --version` matches required major |
| "missing env var X" | `[ -n "${X:-}" ] \|\| fail` |
| "pip install -r requirements.txt" | importable-module probe (`verify.py`) |

If no precondition is mechanically checkable from the logs, **emit no script** — a skill without `verify.*` is valid. Never fabricate a check.

The synthesis prompt (`04 §1`) already invites the optional `file:scripts/verify.sh` block under exactly these rules.

---

## 5. How agents and the harness use it

- **Agent runtime:** on loading a skill whose `## Verify` names a script, run it first. On `VERIFY: fail`, apply the `fix=` hint (or surface it) **before** attempting the task — this is the fail-fast / self-correct path the brief asked for.
- **Synthesis gate (`04 §5.4`):** the engine runs `verify.*` in dry-run inside the worktree. A skill whose own verify script errors out (crashes vs. clean `fail`) is rejected — a check that can't run is worse than no check.
- **Discoverability:** `_meta.json` needs no new field — `core/skills.py` already reports `has_scripts`; the `## Verify` section names the exact file. (Optional future: a `has_verify` convenience flag, but it's redundant with `has_scripts` + the section, so it's deliberately omitted.)

---

## 6. Worked example (ties the whole loop together)

1. Five agents log `error[E0463]: can't find crate for `ratatui`` while building, across 3 task contexts; two later log the fix (`add ratatui to [dependencies]`).
2. Reflection: normalize → signature `e0463 cant find crate for ratatui`; T1 clusters all 5; `n=5, d=3, g=0.6`; `W ≥ Θ`; `mode=create`; budget-fits the medoid + 2 fixes.
3. Synthesis: emits `cargo-build-recovery/SKILL.md` (with the `## Failure → Fix` row), `_meta.json` (`failure_signatures:["e0463 cant find crate for ratatui"]`, `cluster_key`), and `scripts/verify.sh` (checks `cargo` + `$TMPDIR` exec).
4. Harness: schema-validates, runs `verify.sh` (ok), commits to `reflect/e0463xxxx-20260627`, opens a PR.
5. Next agent that hits the build runs `verify.sh` first, gets a clean `VERIFY: ok` (or a `fix=` if its `$TMPDIR` is noexec), reads `## Failure → Fix`, and resolves before reproducing the failure. If it still recurs with `skill_applied=cargo-build-recovery`, the skill's `review_score` decays and it re-enters synthesis as `update`.
